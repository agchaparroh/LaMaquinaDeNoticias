# Error Report: Referential Integrity Validation Failure
**Date**: 2025-01-22
**Time**: 03:35 UTC
**Status**: PARTIALLY RESOLVED

## Summary
Fixed the primary validation error by correcting field name mismatch in PayloadBuilder validation. Changed `id_temporal_hecho` to `id_temporal` to match the persistence model. The pipeline now processes articles successfully but still shows validation warnings during payload construction that need further investigation.

## Error Details
- **Type**: Validation Error
- **Message**: "Validación fallida para payload articulo: 12 errores encontrados"
- **Location**: PayloadBuilder._validar_integridad_referencial()
- **Impact**: Prevented article persistence to Supabase

## Root Cause
Field name mismatch in referential integrity validation:
- Validation code was looking for `id_temporal_hecho` in facts
- HechoExtraidoItem model expects `id_temporal`
- Facts from phase 4 only had `id` field, not `id_temporal` or `id_temporal_hecho`

## Solution Implemented

### 1. Fixed validation field name (payload_builder.py line 87):
```python
# Before:
if 'id_temporal_hecho' in hecho:
    ids['hechos'].add(hecho['id_temporal_hecho'])

# After:
if 'id_temporal' in hecho:
    ids['hechos'].add(hecho['id_temporal'])
```

### 2. Added fact mapping in payload builder (lines 410-434):
```python
# Added mapping to ensure facts have correct id_temporal field
for item in hechos_extraidos_data:
    id_hecho = str(item.get('id_hecho', item.get('id', item.get('id_temporal', ''))))
    hecho_mapeado = {
        'id_temporal': id_hecho,
        # ... other fields mapped
    }
```

## Remaining Issues
The fix resolved the immediate field name issue but revealed deeper problems:
1. Facts are assigned `id_temporal` from `id_hecho` field
2. Relationships reference numeric IDs that don't match the string IDs in facts
3. Background processing still fails validation despite API returning success

## Next Steps
1. Investigate why relationships have different IDs than facts
2. Check phase 7 normalization for how relationship IDs are assigned
3. Ensure consistent ID usage across all phases
4. Add more comprehensive testing for the full pipeline flow

## Lessons Learned
- Field name consistency is critical across all models and validation
- The pipeline has graceful error handling that returns success even when background processing fails
- Multiple layers of ID mapping can create confusion and validation errors
- Debug logging is essential for tracking data transformations
